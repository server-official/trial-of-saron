# TRIAL OF SARON

A browser-based game: you vs. a machine learning model, both classifying and
localizing targets in SAR (Synthetic Aperture Radar) chips. Draw a bounding
box, pick one of 5 classes, confirm — then see the model's prediction and the
ground truth laid over the same image. Score a point if your box clears
**IoU > 0.5** against the ground truth *and* your class is correct. Ten
rounds, most points wins.

Pure static site (HTML/CSS/JS, no build step, no backend) — designed to run
directly on GitHub Pages. This repo ships with a small synthetic placeholder
dataset so it works out of the box; swap in your real SAR data before you
publish it for real use.

## 1. Folder structure

Drop your three folders in at the repo root, replacing the placeholder
content already there. Each class subdirectory name **must exactly match** a
`name` field in `classes.json`, and `class_id` in every label file must match
that class's `id` in `classes.json`.

```
training/
  cargo/
    img001.jpg
    img001.txt      <- YOLO label: class_id cx cy w h
    img002.jpg
    img002.txt
  tanker/
    ...
  fishing/
  passenger/
  other/

test/
  cargo/
    img101.jpg
    img101.txt      <- ground-truth YOLO label
  tanker/
  ...

predictions/
  cargo/
    img101.txt       <- model's YOLO prediction for test/cargo/img101.jpg
                          (same class subfolder + same filename as the
                          matching test image)
  tanker/
  ...
```

- **training/** — used only by the in-game "Training Database" tab, so the
  player can study labelled reference examples any time.
- **test/** — the pool the game draws rounds from. Each image needs a
  matching `.txt` ground-truth label.
- **predictions/** — your model's precomputed predictions, one `.txt` per
  test image, in the same class subfolder and with the same filename
  (minus extension) as its `test/` counterpart. Images with no matching
  prediction file are skipped by the game.

**Label format** (space-separated, one target per line — the game reads the
first line of each file):

```
class_id cx cy w h [confidence]
```

`cx cy w h` are normalized 0–1 (standard YOLO convention). `confidence` is
optional and only meaningful in `predictions/` files.

Supported image formats: `.jpg .jpeg .png .tif .tiff .bmp`.

## 2. Configure your classes

Edit `classes.json`. The array order fixes each class's `id` (used as
`class_id` in your label files), and `name` must match your folder names
exactly:

```json
{ "id": 0, "name": "cargo", "label": "CARGO VESSEL", "color": "#00ff9c" }
```

## 3. Build the manifest

GitHub Pages can't list folder contents at runtime, so a `manifest.json`
file (an index of every image/label/prediction path) has to be generated
ahead of time.

**Automatically (recommended):** the included GitHub Actions workflow
(`.github/workflows/deploy.yml`) regenerates `manifest.json` and deploys to
Pages on every push to `main`. Nothing to do — just push your folders.

**Manually (for local testing):**
```
python3 scripts/generate_manifest.py
```

## 4. Enable GitHub Pages

Repo → **Settings → Pages** → Build and deployment → Source: **GitHub
Actions**. After your next push, the workflow builds and deploys
automatically; the URL shows up on that same Settings page.

To test locally first:
```
python3 -m http.server 8000
```
then open `http://localhost:8000`.

## 5. Replace the placeholder dataset

Everything currently in `training/`, `test/`, and `predictions/` is
synthetic filler generated by `scripts/generate_sample_data.py`, just so the
game is playable immediately. Delete those folders' contents, drop in your
real SAR chips + YOLO labels + model predictions following the structure
above, then rebuild the manifest (step 3).

## File map

```
index.html                       game shell + all views
css/style.css                    hacker/radar HUD theme
js/iou.js                        IoU math + YOLO label parsing
js/manifest-loader.js            fetches classes.json / manifest.json / labels
js/canvas.js                     image display, bbox drawing, overlay rendering
js/database.js                   training database browser + modal viewer
js/main.js                       game state machine (rounds, scoring, screens)
classes.json                     the 5 class definitions (edit this)
manifest.json                    generated — do not hand-edit
scripts/generate_manifest.py     scans training/test/predictions -> manifest.json
scripts/generate_sample_data.py  optional: regenerates the placeholder dataset
.github/workflows/deploy.yml     auto-builds manifest + deploys to Pages
```

## Notes

- Everything runs client-side; no data leaves the browser beyond the static
  file fetches GitHub Pages already serves.
- If a round pool ends up with fewer than 10 eligible test images (i.e. test
  images that have a matching prediction file), the match simply runs as many
  rounds as are available.
- Only the first label line in each `.txt` file is used — Trial of SARON
  expects one target per image.
